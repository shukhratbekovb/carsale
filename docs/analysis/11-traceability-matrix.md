# Carsale — Матрица трассируемости (RTM)

> Версия: 1.0 · Дата: 2026-06-28 · Источник: [PRD](../PRD.md) · Автор: Системный аналитик

Матрица обеспечивает сквозную трассируемость: **цель PRD → требование → use case → диаграмма → acceptance criteria (тест)**.  
Пробелы в матрице явно помечены — это ценный результат анализа.

---

## Цели PRD

| ID | Цель |
|----|------|
| G-1 | Стать лидирующей платформой доверенных сделок с автомобилями в Узбекистане |
| G-2 | Монетизация через разовую оплату; LTV/CAC > 3 |
| G-3 | Снизить медианное время продажи < 14 дней (North Star — ликвидность) |
| G-4 | Deal Rating для 100% активных объявлений в MVP |
| G-5 | Верифицировать ≥ 60% продавцов через SMS/OneID к концу 6 месяцев |
| G-6 | Доля жалоб на скам < 0.5% от объявлений |
| G-7 | MAU > 10 000 за 6 месяцев |

## Анализ пробелов

### Непокрытые цели
Все 7 бизнес-целей (G-1 — G-7) покрыты хотя бы одним требованием.

### Требования без use case (нуждаются в внимании)
| Требование | Проблема |
|-----------|---------|
| FR-17 Авто-описание LLM | Отдельный UC не написан (P1); включается как feature в UC-08 |
| FR-18 LLM чат-бот | Отдельный UC не написан (P1); реализуется как widget на UC-02 |
| FR-19 Кабинет дилера | P2; требует отдельного UC при начале Фазы 2 |
| FR-20 Повреждения по фото | P2; требует UC при начале Фазы 2 |
| FR-21 CIS-инфраструктура | P2; архитектурная NFR, не пользовательский UC |
| NFR-7, 10, 12–17 | Техн. требования без UC — норма; проверяются через тесты инфраструктуры |

### Требования без acceptance criteria
- Все P0 требования имеют acceptance criteria (в 04-functional-requirements.md).
- P1/P2 — acceptance criteria будут уточнены при входе в соответствующую фазу.
