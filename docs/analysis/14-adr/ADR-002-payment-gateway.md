# ADR-002: Выбор платёжного шлюза — Click + Payme

- **Статус:** Принято
- **Дата:** 2026-06-28
- **Автор:** Системный аналитик

---

## Контекст

Carsale принимает оплату за публикацию объявлений и расширенные отчёты (FR-14). Оплата должна проводиться через PCI DSS-сертифицированный шлюз без хранения данных карт на серверах Carsale (BR-6, NFR-17). Целевой рынок — Узбекистан.

Требования:
- PCI DSS compliance (данные карт через шлюз)
- UZ-рынок: Uzcard, Humo карты
- REST API + webhook уведомления о статусе
- Возможность refund

---

## Решение

Интегрировать **Click** (приоритет) и **Payme** (параллельно или Sprint +1) как два независимых платёжных шлюза. Пользователю предлагается выбор способа оплаты.

**Click** — первый в разработке (более широкая база пользователей UZ).  
**Payme** — второй шлюз; обеспечивает failover и охватывает другую часть аудитории.

---

## Последствия

**Что становится проще:**
- Оба шлюза — лидеры UZ рынка онлайн-платежей; высокое доверие пользователей
- PCI DSS scope полностью на стороне шлюза (Carsale — SAQ A)
- Два шлюза = failover: если Click недоступен → Payme
- Широкий охват: Click + Payme покрывают ~80%+ UZ online-плательщиков

**Что становится сложнее:**
- Два разных API = удвоение кода интеграции; но API-схожи
- Разные форматы webhook → нужны два handler'а

**Митигация:**
- Абстракция PaymentGateway interface; конкретные реализации Click и Payme
- Идемпотентность webhook: `gateway_transaction_id UNIQUE` в Payment table
- Polling fallback если webhook не получен за 5 мин

---

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|-------------|-------------------|
| **Только Click** | Риск единой точки отказа; не покрывает Payme-пользователей |
| **Только Payme** | Симметричный риск; меньше база пользователей |
| **Uzum Pay** | Новый игрок; меньше зрелость API; рассмотреть в Фазе 2 |
| **Международный шлюз (Stripe)** | Не работает в Узбекистане для UZS; карты Visa/MC — не основная аудитория |
