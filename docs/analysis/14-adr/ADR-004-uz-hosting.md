# ADR-004: Хостинг только в юрисдикции Узбекистана

- **Статус:** Принято
- **Дата:** 2026-06-28
- **Автор:** Системный аналитик

---

## Контекст

Закон Республики Узбекистан «О персональных данных» №ЗРУ-547 от 02.07.2019, статья 8 требует, чтобы персональные данные граждан Узбекистана хранились и обрабатывались исключительно на серверах, физически расположенных в юрисдикции Республики Узбекистан.

Carsale обрабатывает PII: номера телефонов (хеши), email, паспортные данные (через OneID), история чатов.

Нарушение требования локализации → административная ответственность; риск блокировки платформы; репутационный ущерб.

---

## Решение

**Весь production-хостинг Carsale физически размещается в Узбекистане.** Это включает:
- Серверы основного приложения (Core API, Web, ML Service)
- Базы данных (PostgreSQL primary + replica)
- Object Storage (фото объявлений)
- Redis, RabbitMQ

**Варианты реализации (выбирается при ответе на OQ-5):**
- Beeline UZ Cloud (облачный провайдер с UZ дата-центром)
- Ucell / UzCloud
- Colocation в UZ дата-центре (собственное оборудование)

**CDN:** Cloudflare допускается для раздачи статики и blurred-фото (без PII), но origin-серверы должны быть в UZ. Если Cloudflare недоступен → локальный CDN.

**Исключения (без PII):**
- Внешние SaaS: SendGrid, Firebase, LLM API — принимают только обезличенные данные (BR-8, NFR-22)
- Cloudflare CDN: только blurred фото (без персональных данных)

---

## Последствия

**Что становится проще:**
- Соответствие ЗРУ-547 с первого дня → нет правовых рисков
- Низкая latency для UZ-пользователей (сервера близко)

**Что становится сложнее:**
- Выбор хостинг-провайдера ограничен UZ-рынком
- Меньше зрелость UZ-облаков vs AWS/GCP (SLA, managed services)
- Невозможно использовать managed PostgreSQL/Redis от AWS для production
- Более высокая операционная сложность (self-managed or UZ-managed)

**Митигация:**
- Выбор наиболее зрелого UZ-провайдера с SLA ≥ 99.5%
- Собственный DevOps компетентный в self-managed PostgreSQL/Redis
- Резервное копирование (backup) — также в UZ (Backup Regulation compliant)

---

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|-------------|-------------------|
| **AWS eu-west / ap-southeast** | Нарушение ЗРУ-547 ст. 8 (PII не в UZ юрисдикции) |
| **GCP us-central** | То же нарушение |
| **Гибридный (часть в AWS, часть в UZ)** | Риск cross-border transfer PII; сложность compliance audit |
| **Ждать появления AWS/GCP региона в UZ** | AWS/GCP не объявляли UZ region; неопределённые сроки |
