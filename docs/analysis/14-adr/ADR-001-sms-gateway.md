# ADR-001: Выбор SMS-шлюза — Eskiz UZ

- **Статус:** Принято
- **Дата:** 2026-06-28
- **Автор:** Системный аналитик

---

## Контекст

Carsale использует SMS OTP для регистрации и входа пользователей (FR-01). Для отправки SMS в Узбекистане необходим local SMS-шлюз (международные шлюзы типа Twilio дороже, имеют задержки доставки и иногда блокируются UZ-операторами).

Требования к шлюзу:
- Доставка OTP ≤ 30 сек (NFR-5)
- Работа с UZ-номерами (+998)
- REST API
- Delivery receipt/webhook для мониторинга

---

## Решение

Использовать **Eskiz UZ** (`notify.eskiz.uz`) в качестве основного SMS-шлюза.

---

## Последствия

**Что становится проще:**
- Низкая задержка доставки (локальный шлюз, прямые договоры с UZ-операторами)
- REST API с документацией на русском/узбекском
- Стоимость ниже международных альтернатив для UZ-рынка
- Delivery receipt webhook доступен

**Что становится сложнее:**
- Единая точка отказа (только один шлюз в P0)
- Зависимость от стабильности Eskiz UZ (нужен мониторинг delivery rate)

**Митигация рисков:**
- Резервный шлюз (nikita.uz или playMobile) в конфигурации; переключение через env variable
- Retry с exponential backoff (2 попытки, интервалы 2 сек и 5 сек)
- Алертинг: delivery rate < 90% → PagerDuty

---

## Рассмотренные альтернативы

| Альтернатива | Причина отклонения |
|-------------|-------------------|
| **Twilio** | Дороже; задержки доставки в UZ; периодические блокировки UZ-операторами |
| **Nikita.uz** | Менее зрелое API; рассматривается как резервный вариант |
| **PlayMobile** | Ориентирован на массовые рассылки; OTP не основной кейс |
| **Собственный SMS-шлюз** | Избыточно для MVP; требует договоров с каждым оператором отдельно |
