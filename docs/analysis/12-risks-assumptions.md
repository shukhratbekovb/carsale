## 1. Реестр рисков

Оценка: **Вероятность** (В/С/Н) × **Влияние** (В/С/Н) = Уровень риска (Критический / Высокий / Средний / Низкий).

| ID | Риск | Категория | Вероят. | Влияние | Уровень | Митигация | Владелец |
|----|------|-----------|---------|---------|---------|-----------|---------|
| R-1 | **Cold start / курица и яйцо**: без объявлений нет покупателей, без покупателей нет продавцов | Продукт | В | В | Критический | Запуск только в Ташкенте; бесплатный период размещения (6 мес.); seed-объявления через партнёрство с дилерами; PR и маркетинг до запуска | PM + BD |
| R-2 | **B2G провал (ГУБДД/страховые)**: переговоры затянутся > 12 мес. или не завершатся успехом | Орг. | В | В | Критический | FR-15 перенесён в P1; MVP работает без этой фичи; «облегчённая история» на данных самой платформы (VIN-история объявлений); начать переговоры параллельно с Фазой 0 | BD + PM |
| R-3 | **Конкуренция Avtoelon**: сетевой эффект лидера, возможен копирование Deal Rating | Рынок | В | В | Критический | Острый дифференциатор: верификация + ML + история; не атака «весь рынок», а нишевый сегмент «проверенных сделок»; скорость выхода | PM + CTO |
| R-4 | **Один крупный скам-скандал**: мошенническое объявление становится публичным, репутационный ущерб | Продукт | С | В | Высокий | ML fraud detection с первого дня (FR-11); очередь модерации фрод-флагов; процедура жалоб; публичный статус платформы по метрике | CTO + Admin |
| R-5 | **Низкое качество ML на малых данных**: Deal Rating недостаточно точен на старте (< 1000 объявлений) | Технич. | С | С | Высокий | Seed-датасет синтетической генерации (ADR-003); градиентный бустинг работает на малых данных лучше DL; MAPE ≤ 15% как порог — не вводить фичу при худшем качестве | ML-команда |
| R-6 | **Недоступность Eskiz UZ (SMS)**: регистрация заблокирована в пиковый момент | Технич. | Н | В | Высокий | Retry с exponential backoff; резервный SMS-шлюз (nikita.uz) в конфигурации; мониторинг delivery rate с алертингом | DevOps + CTO |
| R-7 | **Монетизация душит предложение**: ранний paywall отпугнёт продавцов | Бизнес | С | С | Высокий | Монетизация вводится только при ликвидности > 30%; первые 6 мес. — бесплатное размещение; A/B тест перед включением | PM |
| R-8 | **Дезинтермедиация**: продавцы и покупатели уходят в Telegram/WhatsApp после первого контакта | Продукт | В | С | Высокий | Номер телефона не раскрывается в чате без согласия; ценность (история, Deal Rating, безопасный чат) доступна только внутри платформы | PM + Dev |
| R-9 | **Нарушение ЗРУ-547**: PII попадает на зарубежные сервера (LLM, CDN, аналитика) | Правовой | С | В | Высокий | Все PII только в UZ (NFR-18); обезличивание в LLM-запросах (NFR-22); аудит хостинга; регистрация оператора ПД до запуска | CTO + Legal |
| R-10 | **Недоступность платёжного шлюза**: Click/Payme недоступен → невозможно публиковать (Фаза 1+) | Технич. | Н | С | Средний | Fallback на второй шлюз (если оба — FAILED: объявление сохраняется как черновик); webhook retry; polling статуса | DevOps |
| R-11 | **Утечка данных / взлом**: компрометация PII пользователей или VIN/госномеров | Безопасность | Н | В | Высокий | TLS 1.2+; AES-256; rate limiting; OWASP pentest до запуска; разделение private/public storage; minimal PII collection | CTO + Security |
| R-12 | **Накопление технического долга**: давление сроков MVP приводит к "quick fixes" в архитектуре | Технич. | В | Н | Средний | Модульный монолит с чёткими границами модулей (ADR-006); code review; tech debt backlog в каждом спринте | CTO + TL |
| R-13 | **LLM API latency / стоимость**: LLM-функции дороги или медленны на масштабе (P1) | Технич. | С | Н | Низкий | Кэширование ответов LLM (схожие запросы); оценка cost per request до включения; streaming где уместно | ML-команда |
| R-14 | **Партнёрство OneID не получено**: верификация личности невозможна (P1) | Орг. | С | С | Средний | SMS OTP (FR-01) покрывает базовую верификацию для MVP; OneID = premium-уровень; начать переговоры на Фазе 0 | BD |

## 2. Допущения

Всё, что домыслено при анализе в отсутствие явных данных в PRD. Каждое — кандидат на проверку.

| ID | Допущение | Где применяется | Проверяется |
|----|-----------|----------------|-------------|
| A-1 | Технологический стек: Next.js (frontend), Node.js или Python FastAPI (backend), PostgreSQL, Redis | 09-architecture.md | CTO выбирает до Sprint 0 |
| A-2 | Архитектурный стиль: модульный монолит на старте → микросервисы при нагрузке > 10K RPS | ADR-006 | Ревью архитектуры в Фазе 1 |
| A-3 | ML-модели: Deal Rating — градиентный бустинг (LightGBM/XGBoost); Blur — YOLO или аналог; Fraud — rule-based + image hash | 09-architecture.md | ML-команда выбирает до Sprint ML-1 |
| A-4 | Хостинг: colocated server или UZ-облако (Beeline Cloud / Ucell) с физическим расположением в Узбекистане | ADR-004 | Уточнить: OQ-5 |
| A-5 | CDN: Cloudflare с routing в UZ-edge; если недоступно — локальный CDN | 09-architecture.md | DevOps выбирает до деплоя |
| A-6 | Пользователи предпочитают мобильный браузер мобильному приложению на старте; PWA покрывает базовые потребности | ADR-005 | Проверяется по данным аналитики первых 3 мес. |
| A-7 | Цена объявления < 40% медианы — порог ценовой аномалии для fraud detection | 01-glossary, FR-11 | ML-команда может скорректировать порог |
| A-8 | Deal Rating: ≤ медиана × 0.9 = GREAT_DEAL; 0.9–1.1 = FAIR_PRICE; > 1.1 = OVERPRICED | FR-09, 07-state | Пересматривается на реальных данных |
| A-9 | TTL OTP: 5 минут; max попыток: 3; cooldown после блокировки: 15 минут | FR-01, UC-03 | Продуктовое решение |
| A-10 | Объявление автоматически истекает через 30 дней (если не продлено) | 07-state, 08-data-model | Продуктовое решение |
| A-11 | Cron job для пересчёта Deal Rating при изменении цены: запускается немедленно (not batched) | FR-05, FR-09 | Технически реализуемо; пересчёт < 1 сек |
| A-12 | Email-провайдер: SendGrid (первый выбор) или AWS SES (fallback); выбор до интеграции | 09-architecture, 10-integrations | DevOps + бюджет |
| A-13 | Push-уведомления: Firebase Cloud Messaging для Web Push; VAPID WebPush как стандарт | 10-integrations | CTO |
| A-14 | Первые 100 продавцов привлекаются через direct outreach к физическим продавцам в Ташкенте; без платы за размещение | PRD 10.2 | Маркетинг |
| A-15 | Модерация вручную: только объявления с ML-фрод-флагом; остальные публикуются автоматически | BR-12 | Продуктовое решение; пересматривается при росте фрода |
